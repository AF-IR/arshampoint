# راهنمای استخر چندکلیدی موتور هوش مصنوعی (برای تیم‌ها و شریک‌ها)

این راهنما برای کسانی است که **آرشام پوینت را با شریک یا تیم اجرا می‌کنند**: هر نفر کلید سرویس هوش مصنوعی خودش را دارد و همه از یک استقرار مشترک استفاده می‌کنند. با قابلیت استخر کلید، نیازی به چند سرور یا دوباره‌کاری نیست — همه کلیدها در همان یک متغیر محیطی کنار هم می‌نشینند و سیستم خودشان را تقسیم و تعمیر می‌کند.

## چه می‌کند؟

- **تقسیم بار بین کلیدها**: هر درخواست تولید ارائه از یک کلیدِ **رندوم** شروع می‌شود؛ وقتی دو شریک همزمان ارائه می‌سازند، احتمالاً هرکدام روی کلید متفاوتی فرود می‌آیند و سهمیه/محدودیت نرخ هر کلید زودتر پر نمی‌شود.
- **جابجایی خودکار روی خطا**: اگر کلیدی جواب «شلوغی» (۴۲۹)، «کلید باطل/نامعتبر» (۴۰۱)، «سهمیه تمام» (۴۰۲/۴۰۳)، «خطای سرور» (۵xx) بدهد یا ارتباط شبکه قطع شود، سیستم **بلافاصله کلید بعدی استخر را امتحان می‌کند** (بین کلیدها یک مکث کوتاه فزاینده — ۰٫۶ ثانیه به ازای هر کلید امتحان‌شده). کاربر نهایی چیزی نمی‌بیند؛ ارائه با اولین کلید سالم ساخته می‌شود.
- **خروج فقط وقتی همه شکست خورند**: اگر هیچ کلیدی جواب نداد، آخرین خطا با پیام فارسی (بدون لو دادن نام سرویس زیرین) به کاربر می‌رسد.
- **سهمیه تیم = جمع سهمیه‌ها**: هر کلید سهمیه و رتبه‌بندی نرخ خودش را دارد؛ با استخر، عملاً سهمیه اعضا کنار هم قرار می‌گیرد.

## کلیدها را چطور کنار هم بگذارم؟

### فرمت اصلی — هر کلید داخل یک پرانتز

```
ZAI_API_KEY="(کلید شریک اول)(کلید شریک دوم)(کلید سوم)"
```

مثال (نمونه‌نما — کلید واقعی خودتان را بگذارید):

```
ZAI_API_KEY="(0123456789abcdef0123456789abcdef)(fedcba9876543210fedcba9876543210)(aabbccddeeff00112233445566778899)"
```

فاصله، خط جدید و تورفتگی بین پرانتزها آزاد است؛ این دو معادل‌اند:

```
ZAI_API_KEY="(کلید۱)
(کلید۲)
(کلید۳)"
```

### فرمت‌های جایگزین هم پذیرفته می‌شود

اگر پرانتزی در کار نباشد، کلیدها با ویرگول، خط عمودی یا خط جدید از هم جدا می‌شوند:

```
ZAI_API_KEY="کلید۱, کلید۲ | کلید۳"
```

### قوانین پارسر (از کد `src/lib/mode.ts`)

- کلیدهای **کوتاه‌تر از ۱۶ کاراکتر** به‌عنوان داده بی‌ارزش دور ریخته می‌شوند.
- کلیدهای **تکراری** خودکار حذف می‌شوند.
- **داخل مقدار کلید نباید پرانتز باشد** — پرانتز فقط نقش جداکننده دارد.
- اگر متغیر خالی یا حذف شود، برنامه به حالت SDK محلی برمی‌گردد (در دموی محلی) یا خطای «کلید تنظیم نشده» می‌دهد.

## کجا تنظیم کنم؟

| محیط | روش |
| --- | --- |
| Vercel (پیشنهادی برای تیم) | `Settings → Environment Variables` → کلید `ZAI_API_KEY` با مقدار استخر؛ برای هر سه محیط Production / Preview / Development تیک بزنید؛ سپس **Redeploy** تا مقدار جدید اعمال شود |
| اجرای محلی | فایل `.env.local` کنار پروژه (در مخزن نیست و نبودنش درست است) و ری‌استارت `npm run dev` |
| سرور خودتان | همان سرویسی که env را تزریق می‌کند (systemd/Docker/…) و ری‌استارت سرویس |

تغییر متغیر محیطی به تغییر کد نیاز ندارد — فقط یک redeploy/ری‌استارت.

## ورک‌فلو همکاری روزمره

**افزودن کلید شریک جدید** — کلید او را داخل یک پرانتز جدید به انتهای مقدار اضافه کنید و redeploy کنید. از همان لحظه، درخواست‌های او هم بین کلیدها پخش می‌شود.

**کلید شریک باطل شد؟** — سیستم خودش کنار می‌رود: لاگ سرور خطای `HTTP 401 با کلید …xxxx` می‌دهد (فقط **۴ رقم آخر** کلید لاگ می‌شود تا امن حفظ بماند). آن کلید را از استخر حذف و redeploy کنید. تا آن موقع، درخواست‌هایی که به کلید خرده می‌رسند خودکار روی کلیدهای دیگر می‌روند و ارائه‌ها نمی‌شکنند.

**همه کلیدها شلوغ شدند؟** — پیام فارسی «سرورها در این لحظه شلوغ است…» به کاربر می‌رسد؛ بهترین راه‌حل اضافه کردن کلید بیشتر است، نه افزایش timeout.

## چطور مطمئن شوم استخر فعال است؟

1. وضعیت سرور: `GET /api/status` → در حالت Supabase، وقتی بیش از یک کلید در استخر باشد پیام hint می‌گوید: «… استخر ۳ کلیدی موتور هوش مصنوعی هم فعال است.»
2. لاگ سرور: در خطاها شناسه کوتاه کلید مریی است (`[deck-ai] HTTP 429 با کلید …xxxx`).
3. تست واحد آماده: `npx tsx scripts/test-key-pool.ts` — پارسر، انتخاب رندوم و سناریوهای failover (۴۲۹→۴۰۱→۲۰۰، همه-۴۲۹، خطای ۴۰۰ فوری) را با ماک fetch چک می‌کند.

## عیب‌یابی سریع

| نشانه | علت محتمل | اقدام |
| --- | --- | --- |
| «کلید سرویس هوش مصنوعی تنظیم نشده است» | متغیر `ZAI_API_KEY` خالی/تایپ اشتباه نام | env را پر و redeploy کنید |
| «اعتبار سرویس… در دسترس نیست» | همه کلیدهای استخر باطل یا بدون اعتبار | کلیدها را در پنل سرویس بررسی و استخر را نو کنید |
| «سرورها… شلوغ است» در ساعات پرترافیک | سهمیه کلیدها کافی نیست | کلید اضافه کنید |
| فقط کاربرهای بعضی ساعت‌ها خطا می‌گیرند | یک کلید خاص سهمیه‌اش زودتر پر می‌شود | لاگ را برای `…xxxx` مربوط همان کلید ببینید؛ کلید تازه‌تر اضافه کنید |
| تغییر env اعمال نشد | redeploy/ری‌استارت نکرده‌اید | یک Redeploy بزنید و دوباره `/api/status` را چک کنید |

## نکات امنیتی

- کلیدها فقط **سمت سرور** خوانده می‌شوند (`process.env`) و هرگز به مرورگر کاربر یا خروجی ارائه نمی‌روند.
- فایل `.env*` در `.gitignore` است — کلیدها را کامیت نکنید و در زیپ/اشتراک مخزن قرار ندهید.
- در لاگ‌ها فقط ۴ رقم آخر کلید می‌آید؛ اگر لاگ را با کسی شریک می‌شوید، کلید کامل فاش نمی‌شود.
