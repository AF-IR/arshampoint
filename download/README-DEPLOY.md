# راهنمای استقرار «آرشام پوینت» — نسخه اصلی (Supabase + Vercel + Z.ai)

این سند قدم‌به‌قدم مراحل انتشار **نسخه پروداکشن** وب‌اپلیکیشن تولید پرزنتیشن با هوش مصنوعی را توضیح می‌دهد:
احراز هویت کاربران روی **Supabase**، ذخیره پرزنتیشن‌ها در **PostgreSQL سوپابیس**، تولید محتوا با **Z.ai API** و اجرای سایت روی **Vercel**.

---

## معماری در یک نگاه

| بخش | نسخه اصلی (پروداکشن) | حالت دمو (پیش‌فرض سندباکس) |
|---|---|---|
| فرانت‌اند | Next.js 16 + React 19 + Tailwind + shadcn/ui | همان |
| بک‌اند | Route Handlers خود Next.js (Node runtime) | همان |
| احراز هویت | **Supabase Auth** (ایمیل/رمز، JWT با refresh خودکار) | جدول کاربران محلی + کوکی امضاشده |
| دیتابیس | **Supabase Postgres** — جدول `presentations` با RLS | SQLite محلی با Prisma |
| هوش مصنوعی | **Z.ai API** با کلید `ZAI_API_KEY` (مدل پیش‌فرض `glm-4.6`) | SDK داخلی سندباکس |
| خروجی | HTML تک‌فایلی مستقل (RTL، دو تم، ناوبری کیبورد) | همان |

تشخیص حالت **خودکار** است: اگر سه متغیر Supabase تنظیم شده باشند، برنامه در حالت پروداکشن اجرا می‌شود؛ در غیر این صورت وارد «حالت دموی محلی» می‌شود. نشان وضعیت در هدر صفحه، حالت فعال را همیشه نشان می‌دهد.

---

## مرحله ۱ — راه‌اندازی Supabase

1. وارد [supabase.com](https://supabase.com) شوید و با **New project** یک پروژه بسازید (منطقه نزدیک به کاربران‌تان، مثلاً Frankfurt). پسورد دیتابیس را جایی ذخیره کنید.
2. از منوی چپ **SQL Editor** را باز کنید، سپس **New query**. محتوای فایل `supabase/schema.sql` این مخزن را کامل پیست کرده و **Run** بزنید. این اسکریپت:
   - جدول `presentations` را با کلید خارجی به `auth.users` می‌سازد؛
   - ایندکس `(user_id, created_at desc)` برای لیست سریع کتابخانه هر کاربر می‌سازد؛
   - **RLS** را فعال و سیاست «هر کاربر فقط داده خودش» را اضافه می‌کند.
3. تنظیم احراز هویت: **Authentication → Sign In / Up → Email** را فعال بگذارید. اگر می‌خواهید ثبت‌نام بدون نیاز به کلیک روی لینک باشد، گزینه **Confirm email** را خاموش کنید. (اگر فعال بماند، برنامه پیام «ایمیل تأیید را بررسی کنید» نشان می‌دهد و ورود پس از تأیید ممکن است.)
4. کلیدها را بردارید: **Project Settings → API**
   - `Project URL` → بعداً در `NEXT_PUBLIC_SUPABASE_URL`
   - `anon public` → بعداً در `NEXT_PUBLIC_SUPABASE_ANON_KEY`
   - `service_role` → بعداً در `SUPABASE_SERVICE_ROLE_KEY` *(محرمانه — فقط سمت سرور)*

> امنیت: کلید `service_role` از سیاست‌های RLS عبور می‌کند و فقط در Route Handlerهای سمت سرور استفاده می‌شود. کلیدهای `anon` و `URL` عمومی هستند و در مرورگر مشکلی ندارند؛ دسترسی واقعی داده‌ها همیشه از بک‌اند و با بررسی توکن کاربر انجام می‌شود.

---

## مرحله ۲ — گرفتن کلید Z.ai

1. حساب خود را در پنل توسعه‌دهندگان Z.ai (یا open.bigmodel.cn) بسازید و از بخش **API Keys** یک کلید جدید بسازید.
2. مقدار کلید → بعداً در `ZAI_API_KEY`
3. تنظیمات اختیاری:
   - `ZAI_BASE_URL` — پیش‌فرض `https://api.z.ai/api/paas/v4`
   - `ZAI_MODEL` — پیش‌فرض `glm-4.6` (می‌توانید `glm-4.5-air` و مانند آن بگذارید)

> بدون `ZAI_API_KEY` برنامه در محیط توسعه از SDK داخلی (`z-ai-web-dev-sdk`) استفاده می‌کند؛ اما روی Vercel حتماً کلید را تنظیم کنید چون SDK داخلی آنجا کار نمی‌کند. کلید فقط در Route Handler سمت سرور خوانده می‌شود و به مرورگر کاربر ارسال نمی‌شود.

---

## مرحله ۳ — انتشار روی Vercel

1. کد را در یک مخزن **GitHub** push کنید.
2. وارد [vercel.com/new](https://vercel.com/new) شوید، مخزن را **Import** کنید. Vercel خودکار Next.js را تشخیص می‌دهد — Build Command و Output را دست نزنید.
3. قبل از اولین Deploy، در بخش **Environment Variables** این متغیرها را برای **Production** و **Preview** هر دو اضافه کنید:

   | متغیر | مقدار |
   |---|---|
   | `NEXT_PUBLIC_SUPABASE_URL` | Project URL سوپابیس |
   | `NEXT_PUBLIC_SUPABASE_ANON_KEY` | کلید anon سوپابیس |
   | `SUPABASE_SERVICE_ROLE_KEY` | کلید service_role سوپابیس |
   | `ZAI_API_KEY` | کلید API زد.دات‌ای |
   | `ZAI_MODEL` *(اختیاری)* | پیش‌فرض `glm-4.6` |
   | `AUTH_SECRET` *(اختیاری)* | رشته تصادفی برای کوکی حالت دمو |

4. **Deploy** را بزنید. پس از اتمام بیلد، آدرس `https://your-project.vercel.app` فعال است.
5. برای دامنه اختصاصی: **Settings → Domains** و اتصال دامنه از رجیسترار خودتان.
6. **تست نهایی**: وارد سایت شوید، ثبت‌نام کنید، یک پرزنتیشن بسازید و از دکمه «دانلود HTML» خروجی بگیرید. نشان هدر باید «Supabase فعال» را نشان دهد.

### به‌روزرسانی‌های بعدی
هر push به شاخه `main` به‌صورت خودکار در Vercel deploy می‌شود. برای rollback کافی است از تب Deployments نسخه قبلی را Promote کنید.

## اجرای محلی (اختیاری)

```bash
cp .env.example .env   # مقادیر را پر کنید
bun install
bun run dev            # http://localhost:3000
```

- اگر متغیرهای Supabase را پر کنید، همان رفتار پروداکشن را می‌بینید (ورود از طریق سوپابیس).
- اگر خالی بگذارید، حالت دموی محلی با SQLite اجرا می‌شود (`bun run db:push` برای ساخت جداول دمو).

## پرسش‌های پرتکرار

**خطای «Supabase پیکربندی نشده است» می‌بینم.**
سه متغیر Supabase در محیط جاری تنظیم نشده‌اند؛ در Vercel بخش Environment Variables و در اجرای محلی فایل `.env` را بررسی کنید و پس از تغییر، redeploy کنید.

**ثبت‌نام انجام می‌شود ولی وارد نمی‌شود.**
در پروژه سوپابیس گزینه Confirm email فعال است؛ کاربر باید ابتدا لینک تأیید را باز کند. برای حذف این مرحله، Confirm email را خاموش کنید.

**تولید پرزنتیشن خطای 401/403 از Z.ai می‌دهد.**
کلید `ZAI_API_KEY` نامعتبر یا بدون اعتبار است؛ در پنل Z.ai وضعیت کلید و موجودی را بررسی کنید و در Vercel دوباره ذخیره و redeploy کنید.

**پرزنتیشن‌ها ذخیره نمی‌شوند.**
مطمئن شوید اسکریپت `supabase/schema.sql` در SQL Editor اجرا شده باشد؛ ساختار جدول باید دقیقاً مطابق همان فایل باشد.
